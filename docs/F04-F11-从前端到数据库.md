# F04–F11：从前端一路读到数据库

这是 `E:\REBUILTZIJINGFORUM` 的教学版实现说明。工程提供后端 API，没有与参考工程网页直接适配的前端。下面的 `fetch` 是说明浏览器将来怎样发送请求。

## 固定阅读路线：每个功能都这样找

```text
前端 fetch(方法、URL、JSON、Bearer Token)
  → WebMvcConfig.addInterceptors：哪些路径需要登录
  → AuthenticationInterceptor.preHandle：验 JWT、查 user_account、检查 token_version/封禁
  → XxxController：@PathVariable/@RequestParam/@RequestBody 接收参数，JSON 变 DTO
  → XxxService 接口 → XxxServiceImpl：校验规则、组织 Mapper 调用、@Transactional
  → XxxMapper：JdbcTemplate 的 ? 绑定参数并执行 SQL
  → 数据库行 → XxxEntity → XxxVO → ApiResponse.data → 前端
```

`CurrentUserDTO` 是拦截器从有效 JWT 和数据库查出的可信用户，不能用浏览器 JSON 里的 `userId` 替代。`DTO` 是输入，`Entity` 是数据库行，`VO` 是给网页的输出。`@Transactional` 把同一业务的多次写库放进同一个事务。请求失败由 `GlobalExceptionHandler` 返回 `code/message`。

## F04 评论与回复

```javascript
await fetch(`/api/posts/${postId}/comments`, {
  method: 'POST',
  headers: {'Content-Type': 'application/json', Authorization: `Bearer ${token}`},
  body: JSON.stringify({content: '我也在学 Java', parentId: null,
    imageUrls: ['https://example.com/photo.png']})
});
```

`CommentController.create` 接收 URL 中的 `postId` 和 `CreateCommentDTO`。`CommentServiceImpl.create` 先调用 `PostingPermission.requireCanPost` 验禁言，再调用 `CommentMapper.visiblePost/find` 验帖子、父评论归属，清洗正文并校验最多 9 个 HTTPS 图片地址。随后 `CommentMapper.insert` 写 `comment`，`incrementPostCount` 原子增加 `post.comment_count`，`NotificationServiceImpl.emit` 通知作者。这些写库操作共用事务。`CommentMapper.find` 返回 `CommentEntity`，Service 转成 `CommentVO`；删除后只显示“该评论已删除”，图片列表不再返回。

`CommentController.roots → CommentServiceImpl.roots → CommentMapper.countRoots/roots/previewReplies/accountNames`。根评论 SQL 中 `post_id=?` 限定当前帖子，`parent_id IS NULL` 排除回复，`ORDER BY` 决定热度/时间顺序，`LIMIT/OFFSET` 选当前页。`previewReplies` 的 `root_id IN (...)` 一次接收本页所有根 ID；`ROW_NUMBER() OVER (PARTITION BY root_id ORDER BY id DESC)` 给每棵楼内的回复编号，`rn<=3` 只留预览 3 条。`accountNames` 再用一条 `WHERE id IN (...)` 批量补作者与被回复用户的账号名。因此不是“20 条根评论再执行 20 次回复 SQL/作者 SQL”。`GET /api/comments/{parentId}/replies` 再按 `beforeId` 翻更早回复。`DELETE /api/comments/{id}` 在 `CommentServiceImpl.delete` 验作者/管理员，`markDeleted` 设置 `deleted/deleted_at`，`decrementPostCount` 调整有效评论计数。

## F05 点赞、收藏、浏览

`PUT /api/interactions/posts/{id}/like`：`InteractionController.likePost → InteractionServiceImpl.like → InteractionMapper.postExists → LikeMapper.find/insert → InteractionMapper.changeLikeCount`。`like_record(user_id,target_type,target_id)` 的唯一约束防重复；只有新关系确实插入，才用 `SET like_count=like_count+1` 加计数。取消点赞用 `LikeMapper.delete` 的受影响行数决定是否减计数。评论点赞把目标表换成 `comment`，但调用逻辑相同。

收藏走 `FavoriteMapper` 的关系表，计数仍由 `InteractionMapper` 更新；`GET .../state` 分别读关系和计数，给 `PostInteractionVO`。`POST .../view` 每调用一次增加 PV，不是独立访客 UV。首次点赞/收藏还调用通知 Service；自己操作自己不会收到通知。F05 当前以 MySQL 关系表+事务保证强一致，`RedisLockUtils` 是 F09 可选首页缓存刷新使用的短锁，不代表 F05 已改为 Redis 异步计数。

## F06 关注与关注流

`FollowController.follow → FollowServiceImpl.follow → FollowMapper.activeUser/follows/add/followerCount`。Service 禁止关注自己、被封禁或不存在的用户；`follow_relation(follower_id,followed_id)` 的方向是“谁关注谁”，唯一键保证重复 PUT 不多一行。首次关注通知目标用户。取关走 `FollowMapper.remove`，粉丝数按关系表实时 `COUNT`。`GET /api/follows/feed` 走 `FollowMapper.feed`：`JOIN follow_relation f ON f.followed_id=p.author_id` 的贡献是只找到“我关注的人写的帖子”，`WHERE f.follower_id=?` 把“我”固定为当前登录用户，帖子状态条件排除不可见帖。取关后 JOIN 自然不再命中。

## F07 通知中心

默认同步路径：F04/F05/F06/F10 的 Service 调用 `NotificationServiceImpl.emit → NotificationMapper.insert`。Service 过滤“自己通知自己”；`notification.event_key` 唯一约束保证重试不会多条。列表、未读数、单条已读和全部已读从 `NotificationController` 进入 `NotificationServiceImpl`；`NotificationMapper` 的读写 SQL 都带 `user_id=?`，即使 A 猜到 B 的通知 ID，也改不了 B 的记录。打开 `forum.redis.enabled` 后，未读数先读 `NotificationUnreadCache` 的当前用户 key，缓存缺失回源 `NotificationMapper.unread`，新通知/已读时失效；Redis 故障仍读 MySQL。

可选 RabbitMQ 路径（`forum.rabbit.enabled=true`）：业务事务中的 `emit` 改写 `notification_outbox`；事务提交后 `NotificationOutboxPublisher.publishPending` 扫未发布行，收到 broker confirm 才标记成功；`NotificationQueueConsumer.onMessage → NotificationMessageServiceImpl.handle → NotificationServiceImpl.persistEvent → NotificationMapper.insert`。消费者仍靠 `event_key` 幂等；消息失败有限重试后进入 `RabbitMqConfig` 的死信队列。RabbitMQ 停机时业务记录仍可提交，Outbox 保留待重试。此路径已编译，尚未接真实 RabbitMQ 做停机/恢复验收。

## F08 帖子与用户搜索

默认 `GET /api/search/posts?q=Java&page=1&size=20`（也兼容 `keyword`）走 `SearchController.posts → SearchServiceImpl.posts → SearchMapper.countPosts/posts`。Service 把 `%`、`_`、`!` 转义后通过 `?` 绑定，不能把用户关键词拼成 SQL。帖子 SQL 的 `LOWER(title/summary) LIKE ?` 找标题/摘要，`EXISTS (post_tag JOIN tag)` 让标签名也能命中，`status='PUBLISHED' AND deleted_at IS NULL` 排除不可见帖；`COUNT` 给分页总数，`LIMIT/OFFSET` 给当前页。用户搜索只返回公开字段，排除 `BANNED`。

可选 ES（`forum.search.elasticsearch.enabled=true`）：`SearchServiceImpl` 优先走 `SearchIndexServiceImpl`，出错回退 MySQL。两种后端取得 VO 后都调用 `SearchHighlighter.highlight`：先 HTML 转义原文，再只插入固定 `<em>` 标签；当前是完整关键词高亮，不是 ES 分词片段高亮。`EsPostEntity/EsUserEntity` 是索引副本，`ElasticsearchConfig` 配 HTTP 客户端。F01 注册、F02 修改资料、F03 帖子增删改、F11 审核/封禁调用 `SearchSyncServiceImpl`；它等数据库提交后再用 ID 经 `SearchMapper.indexPost/indexUser` 读取最新事实，并 upsert 或删除索引。管理员 `POST /api/admin/search/rebuild → SearchMaintenanceController.rebuild → SearchIndexServiceImpl.rebuild` 建新物理索引、分页导入、核对数量，最后用 `_aliases` 切换；旧索引保留供人工检查。该教学入口同步执行，数据多时请求可能较慢。ES 外部实例尚未实测；没有持久化的 MQ 增量索引事件，ES 故障期间漏掉的同步需重建。

## F09 首页统计与热门标签

`GET /api/home → HomeController.overview → HomeServiceImpl.overview → HomeMapper.users/posts/postsBetween`。`COUNT(*)` 返回数量而非整行；日期范围固定按 `Asia/Shanghai` 的今天/昨天边界。`GET /api/home/hot-tags?limit=10` 中，`JOIN post_tag` 把标签与帖子关系接上，`GROUP BY t.id` 汇总每个标签，`ORDER BY COUNT(...) DESC` 排出热门。只统计已发布帖子。

默认直接读 MySQL。打开 `forum.redis.enabled` 时先读 `HomeCache` 的 60 秒快照；没命中则用 `RedisLockUtils` 抢短锁并回源 MySQL；抢不到可返回 10 分钟内旧快照，没有旧值仍回源。Redis 故障不会无声返回全 0。缓存 TTL、锁和回源代码已接入，尚未接真实 Redis 做并发/故障测试。

## F10 私信与实时提示

```javascript
await fetch(`/api/messages/users/${targetId}`, {
  method: 'POST',
  headers: {'Content-Type': 'application/json', Authorization: `Bearer ${token}`},
  body: JSON.stringify({clientMessageId: crypto.randomUUID(), type: 'TEXT', content: '你好'})
});
```

`MessageController.send → MessageServiceImpl.send` 先验收件人、不能发给自己、正文长度和重复 `clientMessageId`。再通过 `ConversationMapper` 找或创建两人会话，`ConversationMemberMapper` 建两位成员并更新收件人未读数，`PrivateMessageMapper.insert` 保存正文；同一发送请求重试返回旧消息，不重复加未读。`NotificationService.emit` 另写通知。会话历史和已读接口都先走 `MessageServiceImpl.requireMember → ConversationMemberMapper.find`，所以猜到别人的 conversationId 也不能读。

`GET /api/messages/stream` 是带 Bearer 的 SSE 长连接；`WebSocketConfig.MessageSseHub` 在消息事务提交后向收件人推一条 `message` 事件。SSE 只是本机单向提示，事实仍在 `private_message`；断线后客户端必须按 `beforeId` 补拉历史。浏览器原生 `EventSource` 无法方便地加 Bearer 请求头，需使用支持请求头的流式客户端。当前只支持 TEXT，无图片上传、WebSocket 双向通信或跨实例广播。

## F11 管理后台与禁言

`AuthenticationInterceptor.preHandle` 只判断登录；`AdminChecks.admin` 再判断 `role=ADMIN`。`AdminUserController → AdminUserServiceImpl.changeUser → AdminMapper.setUserStatus + PunishmentMapper.insert + AuditLogMapper.insert`：Service 验目标和状态转换；封禁时递增 `token_version`，旧 JWT 下次被拦截器拒绝。禁言到期有两条触发路径：`PunishmentServiceImpl.expireDueMutes` 定时扫描，或 F03/F04 的 `PostingPermission.requireCanPost → PunishmentServiceImpl.expireUserIfDue` 即时检查；两条路径都条件更新并写解除历史、审计，重复执行不会重复解除。

`AdminPostController → AdminPostServiceImpl.changeStatus/setFlag → AdminMapper + AuditLogMapper`。审批只接受 PENDING；置顶/精华只接受 PUBLISHED；操作和审计共事务。F03 新帖目前默认 `PUBLISHED`，所以“存在审批接口”不等于“默认待审核”。管理员列表分别经 `AdminUserServiceImpl.users`、`AdminPostServiceImpl.posts` 返回 VO，不把密码等敏感字段暴露出去。

## 目前验证到哪里

`mvn test` 以 H2 执行了账号、帖子及 F04–F11 主要 HTTP 调用链，也覆盖评论回复/软删除/图片地址、到期禁言审计、并发私信幂等和安全高亮。真实 MySQL、Redis、RabbitMQ、Elasticsearch、浏览器 SSE 尚未联调；编译通过不等于这些外部系统已经验收。仍未做：F05 Redis 异步计数、F08 持久 MQ 索引事件/ES 原生分词高亮、F10 图片私信和跨实例推送、F11 默认待审核发布流、参考网页适配。

建议每次只学一个接口：先找到 Controller 方法，再打开它用到的 DTO 和 ServiceImpl，顺着每个 Mapper 方法看 SQL 的 `SELECT/INSERT/UPDATE/DELETE`、`WHERE/JOIN/ORDER BY/LIMIT` 各自贡献，最后运行 `FeatureFlowApiTest`，尝试关掉手册自己重写一个最小方法。
